What is being verified

CNTRLPLANE-3926 adds the Go package test/e2e/v2/util/mirrorregistry and opt-in wiring in the v2 AWS lifecycle. It is test infrastructure shared by the OCPSTRAT-3316 stories: it provides a registry that hosted-cluster nodes can pull from, so later tests can assert image-mirroring behaviour (IDMS, --registry-overrides). One Setup call does the following:

1 · Deployregistry (TLS, PVC) in an owned namespace, writable, internal only
→
2 · Copyimages by digest through the internal Service (in-cluster oc Job)
→
3 · Lockrestart read-only (pushes → 405)
→
4 · Exposepassthrough Route, anonymous read, verified TLS
→
5 · Returnhost, CA bundle, []ImageContentSource for hypershift create cluster

Caveats

  • The end-to-end create-guests path with the image-mirroring variant is not run by this PR. Scenario 3 created the HostedCluster with the CLI from the harness outputs, which are the same Result fields that the lifecycle writes (covered by unit tests). The first real run is the CNTRLPLANE-3929 job.
  • The PR's GitHub Actions unit-test job does not yet run the new package: the workflow uses the reusable workflow from main, so the new other shard entry only applies after merge. Local -race runs at the PR head are attached instead (details).
  • The fixture supports OpenShift management clusters only (Route, restricted-v2 SCC, ImageStream), which matches every current consumer. Full release-payload mirroring (CNTRLPLANE-3931) is covered by unit tests and a dry-run only.
