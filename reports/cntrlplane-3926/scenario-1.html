Scenario 1 — Smoke (design validation)

Pre-implementation check of the fixture design with hand-written manifests

Objective
Check the assumptions behind the design decisions (D2–D8) with real resources before writing code, and record the facts the implementation needs. The manifests used here became the reference for the resource builders.
Code under test
None. Hand-written manifests (scripts/smoke/manifests/*.yaml) applied with oc; the PR code is verified in Scenarios 2 and 3
Environment
Management cluster mgmt: OpenShift 4.20.0 (itself a HyperShift hosted cluster on AWS, as in CI); namespace test-mirror-registry; registry quay.io/libpod/registry@sha256:e642e860… (2.8.2); copier image from the openshift/cli ImageStream (oc 4.20.0)
Date
2026-10-12
Verdict
PASS Must-have steps 1–9 OK; discovery steps 10–11 recorded

Findings that shaped the code: the serving certificate CN cannot be the Route host (over 64 characters, RFC 5280), so the CN is short and hostnames are SANs only. restricted-v2 must assign the UID and fsGroup, so builders set no fixed IDs. --keep-manifest-list=true is needed to keep the list digest and copies all architectures. One 4.20 payload is about 22 GiB, which sizes the PVC for CNTRLPLANE-3931. The CI image has no oc, so copying runs in-cluster.

The runbook below is the one in the reproduction kit (scripts/smoke/RUNBOOK.md). It is the executed runbook after sanitization, minus the internal workflow notes listed under kit changes.

Runbook — expected results for every step

Goal: verify the assumptions behind decisions.md with real resources, and record the facts the delegated tasks (T3 builders, T4 copier) need. Fill RESULTS.md as you go (each step has a Record line).

Scope and safety: - Only context mgmt, only namespace test-mirror-registry (+ one cluster-scoped read of the ingress domain, ImageStream and ClusterVersion). Nothing on the parent cluster, no HostedCluster changes. - Every oc call goes through k (= oc --context mgmt). - out/ holds a private key: it stays under .work/ (gitignored). Never paste it anywhere. - Step 10 copies the management cluster pull secret into the test namespace: do not print it; it is deleted with the namespace in step 12. - Time: ~1–2 hours. Steps 1–9 are the must-haves; 10–11 are discovery for later stories.

All commands are run from the repository root in a bash/zsh shell.

1. CA and serving certificate (local, openssl)

cd "$OUT/certs"
cat > ca.ext <<'EOF'
basicConstraints=critical,CA:TRUE
keyUsage=critical,keyCertSign,cRLSign
subjectKeyIdentifier=hash
EOF
openssl genrsa -out ca.key 4096
openssl req -new -key ca.key -subj "/CN=hypershift-e2e-mirror-registry-ca" -out ca.csr
openssl x509 -req -in ca.csr -signkey ca.key -days 30 -extfile ca.ext -out ca.crt

cat > tls.ext <<EOF
basicConstraints=CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=DNS:${HOST},DNS:${NAME},DNS:${NAME}.${NS},DNS:${NAME}.${NS}.svc,DNS:${NAME}.${NS}.svc.cluster.local
EOF
openssl genrsa -out tls.key 2048
### CN is limited to 64 characters (RFC 5280) and $HOST is longer; clients match the SANs, so keep CN short.
openssl req -new -key tls.key -subj "/CN=${NAME}" -out tls.csr
openssl x509 -req -in tls.csr -CA ca.crt -CAkey ca.key -CAcreateserial -days 30 -extfile tls.ext -out tls.crt
openssl verify -CAfile ca.crt tls.crt          # expected: tls.crt: OK
cd - >/dev/null
These mirror what T2 will do in Go (support/certs).

7. Verify from the laptop: anonymous, read-only, TLS verified, digest preserved

### TLS verified against our CA only; anonymous; expect HTTP 200 and body {}
curl -sS --cacert "$OUT/certs/ca.crt" -w '  HTTP %{http_code}\n' "https://${HOST}/v2/"

### Without our CA the TLS handshake must fail (proves verification is real)
curl -sS -o /dev/null "https://${HOST}/v2/" ; echo "exit=$? (expected non-zero, certificate error)"

### skopeo needs a directory with ONLY the CA: a *.key without a matching *.cert there is an error.
mkdir -p "$OUT/ca-only" && cp "$OUT/certs/ca.crt" "$OUT/ca-only/ca.crt"

### Digest preserved for both repositories (manifest list digest == TEST_DIGEST)
for repo in quay.io/libpod/registry "${VIRTUAL_REPO}"; do
  echo "$repo: sha256:$(skopeo inspect --raw --no-creds --cert-dir "$OUT/ca-only" \
    "docker://${HOST}/${repo}@${TEST_DIGEST}" | shasum -a 256 | cut -d' ' -f1)"
done
echo "expected: ${TEST_DIGEST}"

### Pushing through the public Route must fail (read-only)
skopeo copy --all --dest-no-creds --dest-cert-dir "$OUT/ca-only" \
  "docker://${TEST_SRC_REPO}@${TEST_DIGEST}" "docker://${HOST}/route-push-check/registry:x" ; echo "exit=$? (expected non-zero)"
Record: all four outcomes.

Surprises / decisions to revisit

  • Step 10: one payload is ~22 GiB stored. Two consecutive payloads for CNTRLPLANE-3931 share many layers but should be budgeted at ~45 GiB → PVC ~60 Gi there. The default 20 Gi stays right for the guest-IDMS lane (single small images). Mirror time for 22 GiB was not measured (dry-run); 3931 must measure it against the Prow job timeout.
  • Step 10: CopyResult.ReleaseSourceRepositories shape confirmed: per release, the release repository plus the unique component repositories (here 2 entries), all mapped to one mirror repository.
  • Step 4: --keep-manifest-list=true copies all architectures of a manifest list (here 6 manifests, 51.88 MiB instead of a few MiB for amd64 only). It is required to keep the list digest. Fine for small test images; for release payloads (CNTRLPLANE-3931) the standard ocp-release images are single-arch, so size stays per-payload. Keep in mind for PVC sizing if multi-arch payloads are ever mirrored.
  • Step 4: the second copy re-uploaded all blobs (mounts=0) although they already existed in the first repository. Storage is content-addressed (no double disk usage), only transfer time is spent. Not worth optimizing for test images.
  • Step 1: the serving certificate CN cannot be the Route host (> 64 characters, RFC 5280). Use a short CN (mirror-registry) and put hostnames only in the SANs. Folded into RUNBOOK.md and plan.md T2.
