Part B — caller-supplied CA (Options.CA)

6. Generate two CAs locally (PKCS#8 keys, as OpenSSL 3 writes them)

for ca in caller-ca caller-ca2; do
  mkdir -p "$OUT/$ca" && (
    cd "$OUT/$ca"
    openssl genrsa -out ca.key 4096 2>/dev/null
    openssl req -x509 -new -key ca.key -days 30 -subj "/CN=hypershift-e2e-${ca}" \
      -addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign" -out ca.crt
    head -1 ca.key; openssl x509 -in ca.crt -noout -subject
  )
done

Surprises / follow-ups (T7, T8, consuming stories)

  • Step 4: after Teardown, curl --cacert <our CA> fails with exit 60 instead of returning 503. With no passthrough Route matching the SNI, the OpenShift router terminates TLS itself with the default ingress certificate, which our CA does not sign. 503 would only be visible with -k. Not a defect: the runbook expectation was wrong (now corrected). It is also how waitEndpoint(exposed=false) sees withdrawal (TLS failure → not OK).
  • Step 3: the old registry pod shows Failed(terminating) during the read-only restart (phase Failed: the registry exits non-zero on SIGTERM). Harmless with Recreate + PVC; content survived (verify passed).
  • Step 9: the old-CA curl line had a typo (\; made echo part of curl's arguments). The first curl error (exit 60 on /v2/ with the old CA) is still the evidence needed; the extra curl: (6)/(3) lines are from the typo.
  • Timings (small image, 2 copies): Setup 28–55s, Route withdrawal ~2s, read-only restart ~5–10s, Teardown 21s. Useful for budgeting T7 PreCreate; the 20-min harness deadline is generous for single images.
  • The copy Job name is deterministic (mirror-registry-copy-95da31410c) and identical across re-runs; the previous Job is deleted first and resources are cleaned on success, so no leftovers.
  • Harness prints "CABundlePEM": null (the field is nulled on purpose). Cosmetic, harness only.
