## 2. Current Jira contract

[CNTRLPLANE-3927](https://redhat.atlassian.net/browse/CNTRLPLANE-3927), status `To Do`, updated `2026-10-16T07:38:29.864+0000`, summary: **E2e test: validate IDMS propagation from imageContentSources to hosted cluster**.

Current description's acceptance criteria:

1. Creating an HC with `imageContentSources` pointing at the in-cluster mirror results in an IDMS resource in the hosted cluster with matching mirror entries (HCCO path).
2. That IDMS has `machineconfiguration.openshift.io/role: worker`, set by `ReconcileImageDigestMirrors`, used by CPO and HCCO.
3. The corresponding ignition ConfigMap is created in the HCP namespace via CPO / `ignition.ReconcileImageSourceMirrorsIgnitionConfigFromIDMS`; this is a different path from AC1–2, so consider a separate `It`.
4. Follow v2 conventions, `[Feature:ImageMirroring]`, `RegisterXxxTests`, lifecycle test; HC creation must be handled through `create-guests` or a step-registry chain.

Additional context explicitly requests `e2eutil.EventuallyObjects`, file `test/e2e/v2/tests/hosted_cluster_image_mirroring_test.go`, dependency on CNTRLPLANE-3926. Jira line numbers are stale: use the inspected symbols below, not the issue's old line numbers.

CNTRLPLANE-3926 was also read (updated 2026-10-14, `In Progress`). Its fixture provides registry setup/teardown, TLS, reachable address and image-content-source entries. This plan consumes the actual #9996 implementation, not the older 3926 planning document. Parent PR manual validation claims are background, **not validation of 3927**.

### Jira minimum versus recommended assertions

- **Required:** named hosted-cluster IDMS exists, mappings correspond to HC input, worker label, named ignition ConfigMap exists in HCP namespace, discoverable v2 lifecycle registration.
- **Recommended stronger assertions, requiring approval:** exact mappings (no extra/dropped entries in the managed IDMS); fixture provenance preconditions; decoded ConfigMap payload is the intended IDMS with matching mappings and worker label; core-ignition label on the ConfigMap. These catch stale/wrong/empty objects which existence alone would accept.
- **Not proposed:** owner-reference assertion, equality of complete metadata, byte-for-byte YAML, `mirrorSourcePolicy`/fallback policy, actual node consumption of ignition. Do not imply AC3 proves node configuration or successful image pulls.

### End-to-end flow

`HYPERSHIFT_E2E_IMAGE_MIRRORING=true` + external `TEST_PLAN` selecting variant
→ `create-guests` / AWS `PreCreate`
→ fixture Setup / public Route / returned ICS
→ files in `SHARED_DIR`
→ variant CLI flags
→ HC spec (management cluster, HC namespace)
→ HO copies to HCP spec (management cluster, **HCP namespace**)
→ **two independent outputs**:

1. HCCO → hosted-cluster config API → cluster-scoped `ImageDigestMirrorSet/cluster`.
2. CPO → management API → `ConfigMap/<ControlPlaneNamespace>/ignition-config-40-image-content-source` with serialized IDMS in `data.config`.

No fixture/lifecycle gap for creating a positive HC was found. Execution selection is intentionally opt-in and remains external to 3927; a default AWS run does not exercise this feature. No new environment variable or fixture-artifact reader is needed under the chosen contract below.

## 4. Decisions to hand to implementers

These are concrete proposed choices, not claims that they are already implemented. Approve the decision set before delegation; an implementer must not substitute alternatives silently.

| ID / problem | Chosen behavior | Evidence / rejected alternative and reason |
|---|---|---|
| D1 — test lifecycle | One feature-scoped Describe with `[sig-hypershift][Jira:Hypershift][Feature:ImageMirroring]`, Ginkgo labels `lifecycle`, `image-mirroring`; proposed registrar `RegisterHostedClusterImageMirroringTests(getTestCtx internal.TestContextGetter)`, following S11. Two independent `It`s: hosted IDMS + label; ignition CM + decoded payload. No Ordered/Serial required for these read-only assertions; no Informing label. | Jira + S11. Reject creation/patching HC inside specs and combining both paths into one `It` (would hide CPO result after HCCO failure). No change to `suite_test.go` needed. |
| D2 — missing/empty input | For an explicitly selected mirroring lifecycle test, inability to get HC, nil/empty ICS, blank source, zero mirrors, blank mirror, or duplicate source is a **failure with setup diagnostic**, never Skip or success. Snapshot/deep-copy HC ICS once per `It`. This is a positive fixture contract, not new API validation. | S2 has two nonempty distinct sources. S8 deletes CM when empty and S7 can reconcile an empty IDMS; comparing two empty values would be vacuous. Reject generic no-config Skip for this dedicated lane: it can hide broken lifecycle wiring. Default jobs exclude the label. |
| D3 — prove mirror fixture is actually the input | In each `It`, require the real and virtual source entries from S2 to be present. Read management Route `test-mirror-registry/mirror-registry` (use existing fixture default constants), require nonempty `spec.host`, and require at least one mirror in **each of those two entries** to have exactly that repository hostname (component before `/`, not a string-prefix match). Compare all HC entries downstream, including additional sources. No HTTP or admission re-check. | S2–S4. Stronger precondition: prevents unrelated ICS from satisfying the dedicated fixture scenario. Reject hard-coded runtime hostname, merely searching `.invalid`, or reading JSON through an invented env bridge. Route observation proves configured provenance, not contents/reachability. If parent changes fixture identity/layout, re-review rather than weakening the guard. |
| D4 — oracle / comparison | Expected values are the observed HC input, checked independently against typed IDMS fields. Match independent source entries without ordering dependence, but preserve each source's mirror sequence and multiplicity. Require exact source-entry count and one-to-one correspondence; reject duplicate source entries, missing/extra entries, wrong/swapped sources or mirrors. Do not sort/mutate input slices in place. Labels: only test required keys. | S6–S7, S14. Reject `globalconfig.ReconcileImageDigestMirrors`, ignition serializer, fixture `buildResult`, or equality between the two observed outputs to generate expected values (circular or correlated-bug tests). Reject sorting mirrors away (priority lost), flattening pairs to sets (association/duplicates lost), or comparing entire objects (irrelevant defaults/metadata). |
| D5 — object selection | GET the exact named IDMS on a hosted-cluster client, no namespace; GET exact CM on `tc.MgmtClient` in `tc.ControlPlaneNamespace`. Adapt each getter to the `EventuallyObjects` collection interface with a singleton on success and no synthetic object on error. Explicit group predicate requires exactly one nonnil, correctly identified target; per-object predicates verify content. | S7, S9–S12. Reject LIST-all with worker selector, taking first object, or “any matching IDMS”: unrelated resources can mask a missing managed target, and label selector would hide label loss. Never treat NotFound as successful observation. |
| D6 — client lifecycle / independence | Both specs obtain HC through `tc.GetHostedCluster()` and use `tc.Context`. Only the hosted-IDMS spec opens `tc.GetHostedClusterClientViaPortForward(hc)`, immediately registers `DeferCleanup(client.Close)`, and polls that client. CM spec must not depend on port-forward setup or success of the first spec. | S10. Reject shared BeforeEach that opens hosted client for both, and direct hosted API assumptions (AWS variant need not be publicly reachable from runner). No new credentials/context framework. |
| D7 — ignition assertion depth | Require named CM and `hypershift.openshift.io/core-ignition-config="true"`, nonempty `Data["config"]`, successful YAML decoding to typed IDMS, explicit GVK `config.openshift.io/v1`, kind `ImageDigestMirrorSet`, payload name `cluster`, empty namespace, worker role and D4 mappings against HC. Allow unrelated CM data/metadata; do not demand exact serialized bytes or unknown-field rejection. | S8–S9. Jira only requires existence; stronger checks prove it is the corresponding usable policy rather than an empty/stale FIPS/SSH payload. Reject parsing as MachineConfig/Ignition JSON or searching substrings (can accept wrong type/content). |
| D8 — async state / errors | Use `EventuallyObjects(GinkgoTB(), tc.Context, ...)` independently for each target, explicit 10m cap / 3s interval (existing defaults, S12). Fetch anew each poll with poll context. Missing/wrong observed state, including incomplete/malformed CM payload, returns false + diagnostic reason and can converge; setup expectation errors fail before polling. API errors returned from getter retry under helper's policy, remain visible and timeout. No sleeps/startup waits, no polling for nodes. | Jira + S12 supersede general stateless-test advice for this propagation lifecycle case. Reject immediate asserts on asynchronously produced objects; reject fatal mismatch on first observation. Do not modify shared polling behavior to classify API errors. |
| D9 — diagnostics and linter gap | Use `WithoutConditionDump()` for both waits, with **one-symbol** allowlist addition and analyzer test (S13). Predicates report expected/actual source mappings, label values, payload type/name or YAML error, with object identity. Include HC namespace/name and target location in objectives/log context; report fixture/HC precondition errors explicitly. Do not dump kubeconfigs, secrets, whole HC specs or pull secrets. | S12 Conditions lacks these object types; default dumping adds spurious errors. Reject copying polling implementation or disabling lint. The allowlist addition is a small explicit framework-support change requiring approval. |
| D10 — scope of registration/filtering | Keep feature out of default matrix. Future external plan selects `variant: image-mirroring`, `labelFilter: "lifecycle && image-mirroring"`. Do not add blanket AWS skip/version skip: tests are selected by preconditions, and producing logic is not AWS-specific (fixture provisioning currently is). Dedicated lane must report **two executed passing specs**, not just exit 0. | S1, S11, S15. Reject assuming textual `[Feature:ImageMirroring]` is a Ginkgo decorator label, and changing CI/default plans in 3927. |

**Non-vacuity summary:** nonempty fixture-backed input before any comparison; exact named GET rather than arbitrary/list match; collection cardinality predicate; both mappings and labels observed on real IDMS; nonempty typed payload observed on real CM; each path independently executed; combined gate requires two non-skipped specs. A successful unit comparison or Ginkgo dry-run is not a propagation pass.
