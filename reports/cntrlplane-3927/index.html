What is being verified

CNTRLPLANE-3927 adds the e2e v2 lifecycle test test/e2e/v2/tests/hosted_cluster_image_mirroring_test.go ([Feature:ImageMirroring], labels lifecycle, image-mirroring). The HostedCluster is created by create-guests with the opt-in image-mirroring variant of CNTRLPLANE-3926, whose mirror fixture supplies the CA and two image content sources. The test checks that the HostedCluster's spec.imageContentSources reach two outputs that are produced by independent controllers, in two independent Its:

InputHC spec.imageContentSources from the fixture (real + virtual source, one mirror each)
→
HOcopies it to the HostedControlPlane
→
Spec 1 · HCCOhosted ImageDigestMirrorSet/cluster, label role: worker
Spec 2 · CPOHCP ConfigMap ignition-config-40-image-content-source, data.config = IDMS YAML

Each spec compares its output with the HostedCluster spec, never with the other output, so a bug shared by both producers cannot hide. The comparison is exact: entry order is ignored, mirror order and multiplicity are kept, and missing, extra or duplicate sources fail.

How to verify independently

Caveats

  • The producers exercised are the CPO/HCCO of the 4.20.0 release payload, not code built from this branch. The change is test-only, so this validates the tests against a real producer; current-main producers are covered by the CNTRLPLANE-3929 job.
  • One live run on one management cluster, not the five consecutive reliable CI runs that CNTRLPLANE-3922 asks for before making the job required.
  • Negative cases (wrong labels, missing or reordered mirrors, wrong ConfigMap, malformed payload) are covered by the unit tests, not by the live run.
