TC-PROP-001. Live Build and Project update propagation

Verification limitation

Propagation, ownership, routing and restoration passed. Exact trigger attribution cannot be proven with existing behavior. This tracing limitation predates the PR; no functional defect was observed.

Plan v4 requires the formal status blocked when exact source-watch attribution cannot be proven. The propagation checks completed successfully; the unproven assertion remains open.

Objective

Verify automatic propagation from independent Build and Project updates and retain source-watch/reconciliation evidence.

Preconditions

  • Healthy 5.1 HC; PR CPO and HCCO running digests verified before mutations.
  • Build marker uses buildDefaults.env; Project marker uses projectRequestMessage. No singleton deletion.
  • 5-second polling, 300-second projection bounds, separate source watches and 30-second post-restoration observation.

Execution

  1. Snapshot both sources, both observed ConfigMaps and the HCP UID.
  2. Start independent Build and Project API watches.
  3. Change only Build; verify Build projection and unchanged Project. Then change only Project and verify unchanged Build.
  4. Check exact HCP owner UID and absence of same-name destinations in every guest namespace.
  5. Restore each spec separately; verify both projections and 30 seconds of stable owned data.
