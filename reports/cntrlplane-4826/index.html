Why the bug reproduces on CAPI v1.14.3 and not before

CAPI v1.14 compares Node.status.nodeInfo.kubeletVersion with Machine.spec.version for the Machine UpToDate condition. HyperShift sets the Machine version to the OCP release string. On the 1.14.3 cluster the live values were v1.37.1 for kubelet and 5.1.0-0.nightly-multi-2026-10-27-082258 for the Machine, so the comparison can never be equal and upToDateReplicas never settles at the desired count. On 1.13.4 that comparison does not exist, the counter reaches the desired count immediately, and the old predicate worked. The base predicate required the counter; the head predicate derives completion from the MachineSets instead.
