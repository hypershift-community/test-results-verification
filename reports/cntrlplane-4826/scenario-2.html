What this proves

  • On CAPI v1.14.3, upToDateReplicas sits at 0 while the new Machines are Ready and available and reaches the target count only transiently. The head predicate completes the config-only Replace rollout anyway.
  • Completion metadata advances only after the physical rollout finished; the action snapshot and the continuous samples show no early publication.
  • The release version and the platform template are untouched by a config-only change.
  • The new MachineConfig is actually present on every worker, read back from the host file system rather than inferred from NodePool status.

What this does not prove

  • It does not exercise the zero-desired branch (T6) or a template-only change (T3).
  • It does not show a pre-1.14 CAPI behaviour; this cluster runs v1.14.3 throughout.
