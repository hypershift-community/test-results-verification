Harness correction in this round

The first T6 run (scale-20261029T021722Z (superseded)) reported FAIL because the snapshot helper listed every guest Node in the hosted cluster, and this HostedCluster also runs the T2/T3 pool. The zero state therefore counted the other pool’s three nodes and the scale-back state counted six. The helper now filters guest Nodes on hypershift.openshift.io/nodePool, and the run below is the corrected one. The superseded run is kept in the bundle rather than deleted.

What this proves

  • Scale-to-zero reaches an empty Machine, MachineSet-replica and Node inventory, and scaling back to three creates new Machines and new Nodes.
  • The head predicate does not block on the zero-desired state and does not publish completion metadata for a rollout that is not happening.
  • Workers join well inside the 12-minute threshold after scale-back.

What this does not prove

  • Nothing here changes the release image, the config or the platform template, so this is a regression check rather than direct proof of the fix.
  • The zero state keeps the current MachineSet at revision 1 with zero replicas; the no-current-MachineSet branch is covered only by unit tests in T4.
